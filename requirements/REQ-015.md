# REQ-015　标注工具集 v2（rectangle / ellipse / arrow / pen / highlight，R48 redo）

> ⚠️ **这是 v2，重做版本。** v1（merge 9092d37）已被 revert（commit 79a39a0），因为用户测试发现三个严重问题：
> 1. **没有拖拽实时预览**：拖拽过程中看不到形状，松手才出现
> 2. **画笔/高亮记录不到中间点**：拖拽很长距离只画了起点→终点直线段（DispatcherTimer 跨线程失效）
> 3. **箭头撤销计数 bug**：AddArrowVisual 给 line+head 两个 children 都标 `AnnotationTag(1)`，撤销时只删一个，破坏一致性
>
> v2 必须把这三点作为**硬性 AC**，并增加对应的单元测试覆盖。

## 目标
扩展 R47 数字标注模式（A 键进入），在 A 模式内按 **0/1/2/3/4/5** 切换 6 种工具：
- **0** NumberedBadge（R47 序号，默认）—— 点击放序号
- **1** Rectangle（矩形描边）
- **2** Ellipse（椭圆描边）
- **3** Arrow（箭头：线段 + 箭头头部）
- **4** Pen（画笔：自由路径）
- **5** Highlight（高亮：半透明粗路径）

按住 **Shift** 拖拽约束（矩形→正方形 / 椭圆→正圆）。**Ctrl+Z** 撤销任意类型（统一栈）。**A** 或 **Esc** 退出标注模式（标注保留）。**Enter** 保存 PNG 时所有标注烧入（**手写 BGRA draw，不用 SkiaSharp**）。

## 为什么
R47 只能放数字序号。标注还有"圈出区域"（矩形/椭圆）、"指向元素"（箭头）、"涂改/划重点"（画笔/高亮）等场景。Snipy/Snipaste/ShareX 都有完整标注工具集，是 Ocean Eyes 把"截图 → 标注 → 分享"闭环做完的关键缺口。

## 关键决策（永久记录）

### v1 失败原因 → v2 必须做的事

1. **🔴 实时预览**（v1 缺失，v2 必做）：
   - 每次鼠标 **LeftButtonDown** 时，在 overlay Canvas 上**立即创建**一个"live preview shape"（Rectangle / Ellipse / Line / Polyline）作为占位 visual，加入 Children，用独立字段 `_livePreviewShape` 记住它（**不计入 undo stack**，用 `_livePreviewShape` 字段区分）。
   - 每次 **鼠标移动**事件（不是 LeftButtonUp），更新这个 live preview shape 的几何（Rectangle 的 Width/Height、Ellipse 的 Width/Height、Line 的 EndPoint、Polyline 的 Points 追加点）。
   - **LeftButtonUp** 时：从 Children 移除 live preview shape，创建最终的 `IAnnotationItem` 加入 session + AddShape 把最终 visual 加入 Children（计入 undo stack）。
   - **Shift 约束也要在实时预览中体现**：每次更新 live preview 时检测 Shift 状态。

2. **🔴 鼠标移动事件路径记录**（v1 DispatcherTimer 失效，v2 用更直接的方案）：
   - **不要**用 DispatcherTimer。**两个备选**（v2 worker 二选一）：
     - **方案 A（推荐）**：扩展 `IMouseHook` 接口加 `MouseMove` 事件，让 LowLevelMouseHook 路由 WM_MOUSEMOVE（`MouseMessageType.MouseMove`）。这是根本解决方案，让所有工具都能拿到完整鼠标路径。修改面：`IMouseHook.cs` + `LowLevelMouseHook.cs` + `MouseMessageType` 枚举加 `MouseMove`。
     - **方案 B（如果方案 A 风险大）**：在 SelectionRuntime 内用 Avalonia `InputManager` 或 `Screens.Primary` + 自己的 DispatcherTimer 但**必须**确保 timer 在 UI 线程创建 + UI 线程启动 + UI 线程 Tick（参考 R44 ColorPickerLoupe 的 `_timer = new DispatcherTimer` 模式，它是在 Window 构造时创建，构造本身在 UI 线程）。同时单测覆盖"模拟 N 次 Tick → 笔迹 ≥ N 个点"。
   - 选 A 或 B 都必须通过 AC-5/AC-6 的"100 像素拖拽 → 至少 5-10 个中间点"实测要求。

3. **🔴 Arrow 撤销计数**（v1 bug，v2 必修）：
   - AddArrowVisual 添加 2 个 children（line + polyline head），**必须**都标 `AnnotationTag(2)`（不是 `AnnotationTag(1)`）。
   - AddRectangleVisual / AddEllipseVisual / AddPathVisual（pen/highlight）都标 `AnnotationTag(1)`（1 个 children）。
   - AddBadge 路径 2 个 children（ellipse + text container）标 `AnnotationTag(2)`。
   - RemoveLastAnnotation 读 tag 的 ChildCount 决定删几个。AC-9 的单测 `AddArrow_Visual_Children_Count_Is_Two` 覆盖。

### 架构决策（沿用 v1）

- **三层抽象**（保留 v1 的设计，这部分没问题）：
  - `IAnnotationItem`（接口 marker）+ 6 sealed records：`NumberedBadgeAnnotation` / `RectangleAnnotation` / `EllipseAnnotation` / `ArrowAnnotation` / `PenStrokeAnnotation` / `HighlightStrokeAnnotation`
  - `AnnotationSession`（统一 undo stack）：`PushBadge(x,y) → NumberedBadgeAnnotation` / `Push(IAnnotationItem)` / `Undo() → IAnnotationItem?` / `Clear()` / `Items → IReadOnlyList<IAnnotationItem>`
  - `AnnotationShapeGeometry`（纯函数）：`NormalizeRect` / `NormalizeEllipse` / `ApplyShiftConstraint` / `ComputeArrowHead`
- **`AnnotationTag` 模式**：每个 visual 在 `AnnotationCanvas.Children` 里挂 `AnnotationTag(int ChildCount)`，`RemoveLastAnnotation` 读 tag 决定删几个 children。
- **AOT 安全**：record + sealed + 接口 marker + pattern match（编译时已知 sealed 类型，无反射）。不用 DI / 不用 dynamic / 不用反射构造。
- **工具切换键路由**：0x30 (0) + 0x31-0x35 (1-5)，都在 vkCode 路由的 OCR-lazy gate **之前**（gate 只放 0x41-0x5A 通过）。**A 进入标注模式时默认 `_currentAnnotationTool = AnnotationTool.Number`**（保留 R47 行为）。
- **mouse hook 路由**（Number 工具特殊路径）：Number 工具时 LeftButtonDown 立刻 `session.PushBadge + overlay.AddShape(badge)`，return（不走拖拽）。其他工具走 LeftButtonDown → 移动 → LeftButtonUp 拖拽路径，中间移动事件驱动 live preview。
- **`AddShape(IAnnotationItem)`**：分发到对应 AddXxxVisual。**`NumberedBadgeAnnotation` 也要分发** → 转发到现有 `AddBadge(NumberedBadge)`（不要漏，v1 worker 漏了导致 Number 工具点击没反应，被我手工修）。
