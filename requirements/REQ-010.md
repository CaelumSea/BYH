# REQ-010　二维码识别（Ocean Eyes QR decode，R45）

## 目标
在 Ocean Eyes 框选确认后，新增工具栏 **Q** 键，立即对当前缓存 PNG 做二维码解码；识别成功把内容写入剪贴板，URL 额外在工具栏状态槽提示"已复制 URL，可粘贴到浏览器"。

## 为什么
当前 Ocean Eyes 已能翻译/解释/总结截图中的文字（R40），但二维码这种"扫一下就要拿走内容"的形态没有专门入口 —— 走 OCR 路径既慢又会把 URL 拆成乱字符。二维码有专门的解码算法（ZXing），~50ms 内可拿到原始内容。

## 验收标准
- [ ] AC-1 Ocean Eyes 框选确认后按 **Q**，若缓存 PNG 含 QR Code / Data Matrix / Code 128 等条码，则在 ~100ms 内把解码得到的文本写入剪贴板，并在工具栏状态槽显示"已复制：{前 40 字符}"。
- [ ] AC-2 框选不含任何条码或解码失败时，工具栏状态槽显示"未识别到二维码"，不修改剪贴板，不抛异常，不影响后续 F/J/Z/R/C/Enter/Esc 操作。
- [ ] AC-3 若解码结果是合法 URL（`http://` / `https://` 开头），状态槽显示"已复制 URL：{前 40 字符}"，剪贴板内容为原始 URL（不自动打开浏览器）。
- [ ] AC-4 引入 `ZXing.Net`（纯托管，MIT）作为解码库；在 Windows NativeAOT 发布下 0 trim/AOT 警告；exe 增量 ≤ +300KB（依赖 DLL + 静态调用代码）。
- [ ] AC-5 新增解码器纯函数单元测试 ≥ 5 个（覆盖：QR 成功 / 无条码 / 多条码取置信度最高 / URL 识别 / 异常输入），整体测试套件全过。

## 关键决策
- 2026-07-20 触发键定为 **Q**（QR 助记），与 P/T 同级 —— 在 vkCode 路由的 OCR-lazy gate **之前**插入分支（Q 在 0x41-0x5A 范围内，gate 之后会被吞）。
- 2026-07-20 解码复用现有 `_oceanEyesPng` 缓存（R46 Pin 同款），不重新 BitBlt，零额外截图开销。
- 2026-07-20 不自动打开浏览器（即使识别为 URL），只复制到剪贴板 —— 用户可能正在敏感应用中工作，自动开浏览器会抢焦点。
- 2026-07-20 ZXing 调用必须用静态 `BarcodeReader` API（不走 DI 容器/反射），保证 NativeAOT trim 安全。
